# Residual Risk Register

| ID | Risk | Control/evidence | Residual | Owner/action |
|---|---|---|---|---|
| R-01 | Same-OS-user access to files or loopback API | Loopback, trusted host, mutation token, deployment ACL guidance | Medium | IT must isolate the service identity/data ACL before pilot |
| R-02 | Malformed media exploits parser/runtime | Signature + ffprobe validation, fixed args, timeouts | Medium-high | Use approved patched FFmpeg; consider OS sandbox before production |
| R-03 | Model/runtime attempts network access | Model path must exist; no download code or cloud API | Low | Egress deny remains recommended defense in depth |
| R-04 | Runaway compute or storage | Size/duration/job/retention budgets, single worker, killable timeout | Low-medium | Monitor disk/CPU during pilot |
| R-05 | Transcript error changes meaning | Time-linked source review; no confidence or accuracy claim | High for consequential use | Human verification is mandatory; build domain evaluation before expansion |
| R-06 | Rule-based analysis is mistaken for judgment | Method chip and explicit limitations; deterministic only | Medium | Training and UI copy review in pilot |
| R-07 | Export loses control/provenance | JSON evidence package; user-triggered export only | Medium | Destination DLP/records policy is external to this app |
| R-08 | Deletion misses backups/exports/indexes | Job-tree deletion and retention test | Medium | Exclude data directory from unauthorized backup/indexing; document external copies |
| R-09 | Misconfigured retention/model/storage | Readiness check, env validation, versioned defaults/docs | Medium | IT-owned configuration baseline and review required |
| R-10 | Edited demonstration is mistaken for measured performance or broad product proof | Synthetic-data badges, visible 12×/16× processing labels, raw timing records, claim boundaries, retained raw captures | Low-medium | Reviewers must use measured evidence and pilot gates, not demo runtime, for decisions |
| R-11 | Folder batch escapes its approved root, overwrites files, or leaves uncontrolled output copies | Relative-root containment, link/junction and traversal blocks, non-recursive scan, count/byte budgets, collision checks, no-overwrite writes, explicit cleanup copy boundary | Medium | IT/records owners must approve `STS_BATCH_ROOT`, output ACL/DLP, retention, and operator training |
| R-12 | Output filesystem failure strands work or leaves a partial transcript | Observed monitor futures, deterministic terminal failures, same-directory temporary files, fsync, atomic hard-link publication, failure-injection tests | Low-medium | IT must qualify hard-link support, free space, ACLs, and recovery behavior on the approved batch workspace |
| R-13 | Architecture definitions or evaluation claims drift from implementation | Versioned L1-L3 definitions, AST dependency/symbol checks, named regression traces, rendered-diagram gate, revisioned JSON report | Low | Maintainer must update architecture, eval catalog, tests, risk/backlog, and evidence in the same material change |
| R-14 | Manifest passwords, archive passphrases, OAuth tokens, or credential references are disclosed or retained beyond need | Preview accepts references only, rejects plaintext/ambiguous secret fields, redacts reference targets from API/audit/disk, holds plans in bounded expiring memory, and caps distinct Windows references; actual secret providers do not exist yet | High for future credential/connector paths; low-medium for preview metadata | Security owner must approve provider lifecycle, revocation, acquisition, release, and credential-store threat model before STS-107/109 can be enabled |
| R-15 | Zoom OAuth overreach, SSRF, unsafe redirects, rate-limit failure, or untrusted remote content compromises the workstation | User OAuth with PKCE; minimum pinned scopes; destination allowlist; bounded redirects/downloads/retries; content validation; disabled-by-default connector | High until implemented | Security and Zoom tenant owners must approve scopes, hosts, retry budgets, revocation, and audit behavior before pilot |
| R-16 | Malicious workbook or archive exploits a parser, escapes extraction, or exhausts compute/storage | Implemented preview rejects unsafe ZIP/XML entries, symlinks, expansion, formulas, external/hidden/embedded features, traversal/reserved paths, unsupported formats, and excess rows/bytes with hostile-fixture regressions; archive extraction remains absent | Low-medium for preview; high for future archive extraction | Security owner must approve the separate archive adapter ADR, secret-safe invocation, cleanup, and hostile archive corpus before STS-108 is enabled |
| R-17 | Installer or container dependencies expand privilege or introduce a supply-chain compromise | Runtime dependencies are pinned; `python-multipart` was raised to 0.0.31 after six direct-pin advisories and the narrowed direct audit now reports none; wheel build passes; installer/container/SBOM and a full transitive audit remain open | Medium-high until deployment qualification | IT packaging owner must resolve the `openai-whisper` audit-tool build-metadata blocker, qualify the full transitive set, choose MSIX or WiX/MSI, and approve signing, Windows matrix, distribution, and rollback |
| R-18 | Corporate recordings, production secrets, or sensitive evidence enter Codespaces or an unapproved test service | Synthetic/mock-only Codespaces policy; fake credentials; private ports; no production vault integration; explicit developer stop gate | High for policy breach | Repository owner must enforce documentation, fixtures, secret scanning, and review gates; test real integrations only on approved Windows runners |
| R-19 | UI hides row-level failure, authorization state, network transfer, or external-copy consequences | Deterministic per-row states/reason codes; manifest preview; authentication state; explicit Zoom/extraction boundaries; cleanup and output-copy guidance | Medium-high until tested | Product/accessibility owner must pass STS-113 usability and accessibility matrices before general pilot |
